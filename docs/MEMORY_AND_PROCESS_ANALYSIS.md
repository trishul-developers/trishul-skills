# Project Memories, Workflows, and Process Analysis

This document provides a comprehensive synthesis of project memories, engineering workflows, and governance rules discovered across the user's projects (`trishul-tactical-engine`, `trishul-agent-hub`, `agent-control-plane`), along with the architectural justification for newly introduced skills.

---

## 1. Analysis of Existing Project Memories

### Memory Item 1: Multi-Provider AgentOps (`multi-provider-agentops-2026-10-26.md`)
- **Owner Directive**: Combine Claude Pro, Codex Plus, and Antigravity rather than upgrading to higher-cost single-provider tiers.
- **Role Alignment**:
  - **Codex Sol / Terra**: Tier-1 core engineer (maths, algorithms, complex simulation mechanics).
  - **Claude Opus / Sonnet**: Architect, project manager, reviews, presentation, binding decisions.
  - **Antigravity Gemini Flash**: Mechanical executor, Unity operator, asset pipeline, test runner.
- **Architectural Implication**: Cross-provider tasks require strict role assignment and unambiguous handoff contracts so agents never wander outside their assigned domain.

### Memory Item 2: Hub PM Setup & Messenger Roles (`hub-pm-setup-2026-11-04.md`, `messenger-role-2026-11-05.md`)
- **Team Hierarchy**: Project Manager (`manager`, Claude) $\rightarrow$ Orchestrators (`orchestrator-codex`, `orchestrator-claude`) $\rightarrow$ Native subagents $\rightarrow$ Headless participants.
- **Wake and Wait Rules**:
  - Interactive desktop sessions join over MCP and wait with long-poll `inbox_wait`.
  - Headless workers are started on demand by the hub runner (`thub runner`).
  - Specialists do not poll; their provider orchestrators wake them.

### Memory Item 3: Codex Implementation Leadership (`codex-leads-from-g02-07.md`)
- **Key Shift**: Codex orchestrator and implementor lead core engineering from batch G02.07 onward. Claude orchestrator handles architect contact and checkpoint batch reviews.
- **The Golden Invariant**: **Zero Self-Review**. The implementor never reviews its own work. If Codex implements a batch, an independent Claude subagent must perform the review.

### Memory Item 4: Clean Git Hygiene & No AI Attribution (`feedback-no-ai-attribution.md`)
- **Strict Prohibition**: Never add AI attribution (`Co-authored-by: Claude`, `Generated by Copilot/Codex`, assistant trailers, badges) to commits, pull requests, issues, or code comments.
- **Standard**: Commits must appear indistinguishable from senior human engineering commits.

### Memory Item 5: Standing Merge Authority (`feedback-standing-merge-authority.md`)
- **Standing Authority**: Merge into `main` or the active phase branch when CI is green and independent review is signed off without asking human permission.
- **Escalate Only**: Budget, platform boundaries, hard invariant violations, or repeated failures ($>2$ failed fix rounds).

### Memory Item 6: Explicit State Review Coverage (`feedback-state-review-coverage.md`)
- **Review Integrity**: In code reviews, agents must explicitly distinguish between:
  1. `READ_IN_FULL` (line-by-line inspection).
  2. `GREP_CHECKED` (interface/signature verification).
  3. `UNREAD_OUT_OF_SCOPE` (unverified scope).
- **Prohibition**: Never claim unread areas are sound or bug-free.

## 2. Gaps Identified & Newly Introduced Skills

To institutionalize these policies and prevent repetitive prompt re-engineering across agent sessions, we introduced six specialized multi-agent process skills in `skills/multi-agent-process/`:

### 1. `thub-messenger`
- **Gap Addressed**: Agents lacked a uniform standard for connecting to Trishul Agent Hub (`thub`), polling mailboxes via `inbox_wait`, dispatching headless participants, and detecting dead letters.
- **Solution**: Provides structured recipes and MCP schemas for dependable, asynchronous inter-agent messaging.

### 2. `multi-agent-orchestrator`
- **Gap Addressed**: Uncoordinated model assignment resulting in expensive Claude Opus quota being wasted on log parsing, or Codex reviewing its own pull requests.
- **Solution**: Enforces the specialization matrix, quota budgets, single-writer principle, and the zero-self-review invariant.

### 3. `standing-gate-verifier`
- **Gap Addressed**: Agents dumped thousands of lines of raw test logs into chat, or claimed "tests passed" without parsing NUnit XML report files.
- **Solution**: Executes FastCompile, EditMode, and PlayMode suites, parses test report XMLs, extracts first-failure details ($<50$ lines), and certifies gate readiness.

### 4. `clean-git-committer`
- **Gap Addressed**: Agents repeatedly leaked AI attribution (`Co-authored-by: Claude`) or ran blind `git add .` staging irrelevant files.
- **Solution**: Enforces zero AI attribution, atomic staging by explicit path, commit message decision logging (`Decisions:`), and standing merge execution on green gates.

### 5. `review-coverage-auditor`
- **Gap Addressed**: Reviewers gave blanket "looks good" approvals without indicating which files were actually read versus skipped.
- **Solution**: Mandates explicit classification into `READ_IN_FULL`, `GREP_CHECKED`, and `UNREAD_OUT_OF_SCOPE`.

### 6. `sim-contract-auditor`
- **Gap Addressed**: Simulation code introduced subtle non-deterministic bugs (unseeded `UnityEngine.Random`, GC allocations in tick paths, non-deterministic hash set iterations).
- **Solution**: Provides static analysis regexes and review rules to detect and eliminate non-deterministic simulation patterns before compilation.
