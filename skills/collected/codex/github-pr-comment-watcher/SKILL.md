# GitHub PR comment watcher

Use Python 3 and the installed GitHub CLI (`gh auth status` should succeed). Run scripts from this skill's `scripts/` directory. Pass `--repo OWNER/REPO` explicitly; do not infer a repository from a different checkout.

1. Inspect comments in chronological order with `python scripts/gh_helper.py comments list --repo OWNER/REPO --pr 28`. Fetch an exact raw body with `comments get --repo OWNER/REPO --comment-id ID`.
2. Check assignments with `python scripts/gh_watch.py check --repo OWNER/REPO --pr 28 --role IMPLEMENTOR-1 --repo-dir PATH`. Use `watch` with `--interval 30` for a bounded live poll (and `--timeout 300` when useful). The watcher reports `NO_NEW_HANDOFF` with exit 0 when idle. It does not mark a handoff consumed on inspection.
3. Compare the reported commit and branch with the assignment. For a `START_SHA`, run `python scripts/gh_helper.py git verify --repo-dir PATH --expected-sha SHA --branch BRANCH` before editing. It requires a clean tree, matching branch, and exact HEAD. It also reports the ahead/behind ancestry counts; a later candidate commit should be checked with `--allow-descendant`, which requires additive ancestry and zero behind commits.
4. Once the handoff has been handled, run `python scripts/gh_watch.py mark-consumed --repo OWNER/REPO --pr 28 --comment-id ID --role IMPLEMENTOR-1 --repo-dir PATH`. State is stored at `PATH/.agents/state/pr_watch_state.json`, keyed by repository, PR, role, and comment ID. Use `--state-file` to choose a different ledger.
5. For a response, write the exact Markdown body to a UTF-8 file and inspect it. Publish with `python scripts/gh_helper.py comments post --repo OWNER/REPO --pr 28 --file PATH`. The helper invokes `gh pr comment --body-file`; do not pass multiline handoffs through PowerShell strings.

The watcher accepts handoffs beginning with `[COORDINATOR]`, `[IMPLEMENTOR-1]`, `[IMPLEMENTOR-LOCAL]`, `[REVIEWER-1A]`, or `[REVIEWER-1B]`. Assignment is determined by exact `ASSIGNED_TO:` or `NEXT_OWNER:` role fields, not by merely mentioning a role. A displayed handoff is advisory until its branch, SHA, and scope are verified against the PR and local git state. Posting or consuming is an explicit action; polling does neither.

## Project PR #28 router

`scripts/pr_handoff_router_poll.py` is the reusable Windows poller. Pass `--config PATH` with a JSON file containing workspace, repository, Issue, PR, trusted authors, registry, state prefix, and orchestrator chat UUID. This project's existing five-minute task still invokes `scripts/pr28_router_poll.py`, a small wrapper using `.agents/state/pr28_router_config.json`. The generic router and orchestrator instructions are `.agents/workflows/HANDOFF-ROUTER.md` and `.agents/workflows/ORCHESTRATOR.md`; portable copies live in this skill's `references/` directory.

For the complete reusable architecture and an Issue #26 / PR #28 example, read `.agents/workflows/GITHUB-PR-ROLE-WORKFLOW.md` (also copied to `references/`). The unsandboxed poller checks GitHub and the registry before a model wake. Routine router messages carry only an event key, target UUID, acknowledgment path, and workflow path. The router sends one short role message and records delivery.

The poller uses `gh api graphql` to read new PR conversation comments in chronological order and detect later edits to recent handoffs. Its cursor is a scan cursor; a per-comment and per-revision event journal and acknowledgment files keep blocked roles from stopping independent handoffs. Before waking a model, the unsandboxed script verifies the current handoff, checks for a later target-role result, and resolves the current role UUID. It records superseded/consumed events as `SKIPPED` and failures as `BLOCKED`. Unchanged handoff polls use no model turn, and there is no periodic model health check. Historical role names are normalized to `COORDINATOR`, `IMPLEMENTOR-CLOUD`, `IMPLEMENTOR-LOCAL`, `REVIEWER-A`, or `REVIEWER-B`. Roles listed in config `external_roles` are recorded as `EXTERNAL` without waking a ChatGPT chat; Issue #26 uses Antigravity for `IMPLEMENTOR-LOCAL`. The poller reads the router UUID from the registry's `ROUTER_THREAD:` line. The router receives only an event key, target UUID, and acknowledgment path, sends `check PR and continue`, and writes `DELIVERED` with a Unix timestamp. The Codex Orchestrator owns registry edits and chat replacement. Every observed role-chat `systemError` is reported to it while other routing continues. An unacknowledged delivery older than 15 minutes or a delivered handoff without a durable result beyond `result_timeout_hours` alerts it once. Three consecutive poller errors alert it as well. Use `--dry-run` for read-only inspection. Keep app heartbeats paused while the OS poller is scheduled.
