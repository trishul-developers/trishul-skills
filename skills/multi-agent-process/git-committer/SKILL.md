# Clean Git Committer

This skill enforces strict Git repository hygiene, pristine commit histories, and professional multi-agent version control etiquette as defined across project memories and owner guidelines.

## Hard Rules

### 1. Absolute Ban on AI Attribution
> [!IMPORTANT]
> **Never include AI attribution in commits, PR descriptions, or comments.**
> - DO NOT write `Co-authored-by: Claude <noreply@anthropic.com>`
> - DO NOT write `Generated by OpenAI Codex` or `Assisted by Antigravity`
> - DO NOT append bot badges, AI disclaimers, or model watermarks.
> Commits must appear indistinguishable from senior human engineering commits.

### 2. Stage Explicit Paths Only
- Never run a blind `git add .` or `git add -A`.
- Explicitly stage modified files: `git add src/path/file.py`.
- Never stage temporary artifacts, `.venv`, `node_modules`, `data/*.db`, tokens, or local credentials.

### 3. "Decide-and-Log" Commit Format
Minor specification gaps (naming, constants, enum ordering) should be resolved autonomously and logged directly in the commit message body under a `Decisions:` block:

```gitcommit
feat(combat): implement deterministic target acquisition queue

Prioritize targets by distance squared rather than square root to eliminate
redundant floating-point calculations during tick updates.

Decisions:
- EntityRegistry.cs: tie-break equal distance targets by lowest EntityId.
- CombatConfig.cs: default acquisition radius set to 15.0f.
```

### 4. Standing Merge Authority
When operating as Orchestrator:
- If all verification gates are **GREEN** (compilation, EditMode, PlayMode) and the independent review is **ACCEPTED**:
  - Merge the branch into `main` or the active phase branch **without asking the user for confirmation**.
  - Use a merge commit (`git merge --no-ff`) to preserve branch history.
- Escalate to the human owner only when:
  - There is a budget, scope, or platform decision.
  - Two consecutive fix attempts have failed on the same issue.
  - A hard invariant or architectural contract is violated.

## Standard Commit Workflow

```bash
# 1. Verify working tree status
git status --short

# 2. Stage explicitly
git add Assets/Scripts/Trishul/Runtime/Combat/CombatManager.cs
git add Assets/Tests/EditMode/CombatManagerTests.cs

# 3. Commit with structured decision log
git commit -m "fix(combat): resolve projectile trajectory null check on unit despawn

Decisions:
- CombatManager.cs: suppress projectile tick if target entity was despawned in same frame."

# 4. Push with branch verification
git push origin <branch-name>
```
